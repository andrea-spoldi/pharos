# Row selector (T-026, D-041) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional `rows` dot path on every widget source selects the list inside a wrapped JSON/YAML response before it becomes table rows.

**Architecture:** `pharos-manifest` gains the field and its lint; `pharos-engine` gains a `select` function mirroring the frontend's `field()` and applies it in the file, command and http runners before row conversion, then caps rows at 500. A shared case table keeps Rust and TS dot-path semantics identical.

**Tech Stack:** Rust (serde, serde_json, serde_yaml_ng, insta), SolidJS + vitest.

**Spec:** `docs/superpowers/specs/2026-11-27-data-shaping-design.md` — section *T-026 — Row selector* including its *Implementation notes*.

## Global Constraints

- Nothing executable crosses IPC: no command takes a selector from the frontend; `rows` is read from the stored manifest only.
- `rows` must not change derived capabilities or the consent hash.
- Limits unchanged: 5 MB, existing timeouts, 500 files for file sources; **500 rows after selection for every source type**.
- `pharos-manifest` / `pharos-engine` stay Tauri-free. `app/src/bindings.ts` is regenerated by `cargo test`, never hand-edited; commit it when it changes.
- Lint errors are structured (file, path, message) with fixture tests; snapshots via `INSTA_UPDATE=always cargo test -p pharos-manifest`, then review the diff.
- No wildcards, filters or expressions in `rows` (filtering is slice 14).
- Gates at the end of every task: `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `npm run typecheck -w app`, `npm test -w app`.

## Review Focus

1. **Rust and TS disagree on a path** (numeric segment on an object, non-numeric on an array, index past the end, null in the middle): one shared table, `testdata/dot-paths.json`, read by both suites. Tests in Task 2 (`select_matches_shared_cases`) and Task 3 (`field matches shared cases`).
2. **A file glob where some documents lack the path** must fail with the not-found error naming the file, not silently drop that file. Test in Task 2 (`file_rows_not_found_names_the_file`).
3. **More than 500 selected rows from one file** is cut at 500 with `truncated`. Test in Task 2 (`file_rows_capped_after_selection`).
4. **Changing only `rows` never asks for approval again.** Test in Task 1 (`rows_does_not_change_capabilities`) and Task 2 (`rows_change_needs_no_consent`, end to end through `plan_sync`).
5. **Command text output with `rows` set** errors instead of yielding a `{value}` row. Test in Task 2 (`command_text_output_with_rows_errors`).

  - `pub fn dot_path_problem(path: &str) -> Option<&'static str>` in `validate.rs` (or a small module it uses): `Some(reason)` when the path is empty, has an empty segment (`a..b`, leading/trailing `.`) or contains whitespace.

### Task 2: Engine selection, errors and row cap

**Files:**
- Modify: `crates/pharos-engine/src/run.rs` (`rows()` ~l.123, `read_files` ~l.59), `crates/pharos-engine/src/command.rs` (output parsing ~l.130-138), `crates/pharos-engine/src/http.rs` (~l.139), `crates/pharos-engine/src/lib.rs` (pass `source.rows()` into the three runners, ~l.1075-1110), `src-tauri/src/commands.rs` (error → `ErrorKind::DataError`)
- Test: unit tests in `run.rs`, `command.rs`, `http.rs`; `crates/pharos-engine/tests/run.rs`, `crates/pharos-engine/tests/sync.rs`

**Interfaces:**
- Consumes: `Source::rows()`, `testdata/dot-paths.json` (Task 1).
- Produces:
  - `pub(crate) fn select<'a>(value: &'a Value, path: &str) -> Option<&'a Value>` in `run.rs`: split on `.`; on an object take the key; on an array parse the segment like JS `Number()` for a canonical non-negative integer and index (non-numeric → `None`); on a scalar/null → `None`.
  - `#[derive(Debug, thiserror::Error)] pub enum RowsError { #[error("`rows: {path}` matched nothing in {place}")] NotFound { path: String, place: String }, #[error("`rows: {path}` needs JSON output, but {what}")] NotJson { path: String, what: String } }` — `place` is `"the output"` for command/http and `"<file>"` for file sources; `what` is `"the command printed text"` / `"the response was not JSON"`. Wrapped as `FileError::Rows`, `RunCommandError::Rows`, `HttpError::Rows` and mapped to `ErrorKind::DataError`.
  - `rows(value, max)` keeps its signature; a new `pub(crate) fn select_rows(value: Value, path: Option<&str>, place: &str, max: usize) -> Result<WidgetData, RowsError>` applies the selector then `rows()`.
  - `read_files` applies the selector per parsed document (error names the file), concatenates, then truncates to 500 rows (`MAX_ROWS`) and ORs `truncated` with the file-count truncation.

- [ ] **Step 1: Write failing tests**: `select_matches_shared_cases` (iterates `testdata/dot-paths.json` via `include_str!`); `file_rows_selected_per_document` (two YAML files each `{items:[…]}` → concatenated rows, `_source` set per file); `file_rows_not_found_names_the_file`; `file_rows_capped_after_selection` (one file with 600 items → 500 rows, `truncated`); `command_rows_selects_items` and `command_text_output_with_rows_errors`; `http_rows_selects_data` (existing mock server pattern) and `http_rows_not_found`; `rows_change_needs_no_consent` in `tests/sync.rs` (add `rows` to a widget upstream → plan has no `capability_changes` and `!needs_consent`).
- [ ] **Step 2: Run** `cargo test -p pharos-engine` — FAIL.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** gates — PASS (bindings unchanged unless an error enum is exported; commit if regenerated).
