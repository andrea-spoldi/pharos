# Markdown from a source (T-029, D-044) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `view: { type: markdown }` widget with a source renders markdown text read from a `.md`/`.txt` file, a command's text output, or an http text body.

**Architecture:** The engine makes markdown-with-source runnable, reads `.md`/`.txt` files as text rows, and lets the http runner accept text bodies only when told the view is markdown (a flag derived from the stored manifest). The frontend adds a `MarkdownSourceView` that pulls the text from the first row and reuses the existing mdast `MarkdownView`.

**Tech Stack:** Rust (pharos-engine, ureq), SolidJS + vitest, mdast-util-from-markdown.

**Spec:** `docs/superpowers/specs/2026-11-27-data-shaping-design.md` — section *T-029 — Markdown from a source* including its *Implementation notes*.

## Global Constraints

- Nothing executable crosses IPC; the http text flag comes from the stored manifest's view type, never from the frontend.
- No capability or consent change; engine stays Tauri-free; bindings regenerated by `cargo test` only.
- Limits unchanged: 5 MB bodies, existing timeouts, 500 files, 500 rows. Rendered markdown capped at 256 KB.
- Rendering stays through mdast: no raw HTML, no clickable links (D-026), images as alt text.
- Gates at the end of every task: `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `npm run typecheck -w app`, `npm test -w app`.

## Review Focus

1. **A text body for a non-markdown widget** must still be the JSON parse error, and the `Accept` header for non-markdown widgets stays `application/json`. Test in Task 1 (`text_body_rejected_for_table_view`, `accept_header_follows_the_view`).
2. **An author-set `Accept` header** wins over the markdown default. Test in Task 1 (`author_accept_header_is_kept`).
3. **A `.yaml` file and a `.md` file matched by the same glob** produce a YAML row and a text row, each with `_source`. Test in Task 1 (`mixed_glob_reads_text_and_yaml`).
4. **Content-Type with parameters** (`text/plain; charset=utf-8`, `TEXT/MARKDOWN`) is accepted. Test in Task 1 (`text_content_type_with_params`).
5. **A multi-byte character at the 256 KB boundary** isn't split into an invalid string. Test in Task 2 (`cap_does_not_split_characters`).

**Interfaces:**
- Produces:
  - `(Some(_), ViewType::Markdown)` → `Runnable`.
  - `read_files`: files whose extension (case-insensitive) is `md` or `txt` become `{ "value": <text>, "_source": <rel> }`; with `rows` set → `RowsError::NotJson { path, what: "<rel> is text" }`.
