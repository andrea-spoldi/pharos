# Sidebar navigation (T-024, D-040) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the top bar + dashboard tab strip with a left sidebar (grouped Platform/Mine, collapsible to a 56px rail, global actions in its footer), a slim page header, and a compact top bar below 900px — exactly as the spec describes.

**Architecture:** The dashboard list resource moves from `Dashboards.tsx` up to `Home.tsx` and is passed down to a new `Sidebar` and to `Dashboards`. Two tiny state modules (`sidebar.ts` for open/rail, `viewport.ts` for the 900px breakpoint) are read synchronously on startup. Everything is frontend; the only non-frontend edit is the default window size in `tauri.conf.json`.

**Tech Stack:** SolidJS, @solidjs/router (HashRouter), plain CSS tokens, vitest + @solidjs/testing-library, impeccable (design system).

**Spec:** `docs/superpowers/specs/2026-11-27-sidebar-design.md` — it is the authority for layout, copy, ARIA, CSS and the test list; tasks below point at its sections instead of repeating them.

## Global Constraints

- Frontend only: no engine, manifest, IPC or migration changes; no new dependencies. Only extra file: `src-tauri/tauri.conf.json` window size (Task 5). Bindings drift check must stay a no-op.
- Existing tokens only (`--surface`, `--surface-2`, `--border`, `--fg`, `--muted`, `--radius`, `--accent`, `--accent-wash`, `--space-1..4`); no new colours or shadows.
- `DESIGN.md` and `app/.impeccable/design.json` are generated by impeccable — never hand-edit them.
- Rail labels stay in the accessibility tree via `.sr-only`, never `display: none`.
- The sync status live region stays **always mounted**.
- No browser `prompt()`/`alert()`; reuse `Dialog`/`TitleDialog`.
- Routing unchanged: `/`, `/d/:id`, `/settings`.
- Breakpoints: 900px (sidebar ↔ compact top bar; same value as the existing `WIDE_BREAKPOINT` drag guard), 1280px (default open vs rail).
- Gates at the end of every task: `npm run typecheck -w app`, `npm test -w app`, `cargo test` (bindings drift no-op), `cargo fmt --all --check`.

## Review Focus

1. **Every list-changing action refreshes the sidebar** (create, rename, delete, customize, set/clear landing, sync): one resource, one refetch. Tests in Task 2 (`sidebar_refreshes_after_create_rename_delete`) and Task 3 (`sidebar_refreshes_after_sync`).
2. **Live region announced from the start**: the footer's `role="status"` element exists before any sync begins and survives rail mode. Test in Task 3 (`sync_status_region_is_mounted_before_sync`) and Task 4 (`rail_keeps_sync_status_region`).
3. **Shortcut must not hijack typing**: ⌘\ / Ctrl+\ ignored in inputs, textareas, contenteditable and while a dialog is open. Test in Task 4 (`shortcut_ignored_while_typing_or_in_dialog`).
4. **Storage unavailable**: `localStorage` throwing must fall back to the width default and still toggle for the session. Test in Task 1 (`mode_survives_unavailable_storage`).
5. **Unknown/removed current dashboard** still falls back to the first one (existing behaviour) after the list moves to Home. Test in Task 2 (keep `falls back when the current dashboard disappears` passing against the lifted resource).
