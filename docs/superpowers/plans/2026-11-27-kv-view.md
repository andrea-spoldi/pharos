# kv view (T-027, D-042) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Widgets with `view: { type: kv }` and a source render their first row as label/value pairs.

**Architecture:** One engine match arm makes `kv` with a source runnable; a new `KvView` in `app/src/views/index.tsx` reuses `field()`/`display()` and the existing `.fields` definition-list styling, registered in `WidgetFrame`'s view map.

**Tech Stack:** Rust (pharos-engine), SolidJS + vitest, plain CSS tokens.

**Spec:** `docs/superpowers/specs/2026-11-27-data-shaping-design.md` — section *T-027 — `kv` view* including its *Implementation notes*.

## Global Constraints

- No new IPC, capabilities or consent changes; engine stays Tauri-free; bindings regenerated by `cargo test` only.
- Existing tokens only: labels `--muted`, values `--fg`, rows separated by `--border-soft`, mono via `--mono`. No new colours.
- URLs are plain text, never links (D-026).
- Gates at the end of every task: `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `npm run typecheck -w app`, `npm test -w app`.

## Review Focus

1. **A row whose only fields are nested objects** must still show its keys with compact JSON values, not an empty card. Test in Task 2 (`nested_values_render_as_compact_json`).
2. **A `columns` entry whose path is missing in the row** shows its label with an empty value, never "undefined". Test in Task 2 (`missing_column_shows_empty_value`).
3. **Very long values** (an ARN, a URL) wrap inside the widget instead of overflowing it. Test in Task 2 asserts the value cell carries the wrapping class (`long_values_wrap`); the CSS rule uses `overflow-wrap: anywhere`.
4. **`_source` only when asked**: hidden by default, shown when listed in `columns`. Test in Task 2 (`source_hidden_unless_listed`).

### Task 2: `KvView`

**Files:**
- Modify: `app/src/views/index.tsx` (new `KvView`), `app/src/components/WidgetFrame.tsx` (`views` map ~l.11 gains `kv: KvView`), `app/src/styles.css` (a `.kv` block next to `.fields` ~l.381)
- Test: `app/src/views/views.test.tsx`

**Interfaces:**
- Consumes: `field`, `display`, `columnsFor` from `./fields`; `Frame` (truncation note).
- Produces: `export function KvView(props: ViewProps)` and `export function looksMachineMade(value: string): boolean` (true for `/^arn:/`, `/^https?:\/\//`, a UUID `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`, or `/^[0-9a-f]{12,}$/i`).

Behaviour (spec): first row only; with `columns` → those fields, in order, with labels; without → top-level keys of the first row in key order (`Object.keys` order), `_source` excluded unless listed; object/array values → `JSON.stringify(value)` in mono; other values via `display()`, mono when `looksMachineMade`; `rows.length > 1` → `<p class="muted">+ {n} more rows — use a table view</p>` where n = rows.length − 1; zero rows never reaches the view (the frame shows its empty state).

Markup: `<dl class="kv">` with `<dt>` label and `<dd class="kv-value">` (add `mono` when machine-made or nested). CSS: grid two columns (`max-content` labels, `1fr` values), `gap: var(--space-1) var(--space-3)`, labels `color: var(--muted)`, a `1px solid var(--border-soft)` rule between pairs, `.kv-value { overflow-wrap: anywhere; color: var(--fg) }`, `.kv-value.mono { font-family: var(--mono) }`.
