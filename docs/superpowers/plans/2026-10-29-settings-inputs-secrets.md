# Settings: Inputs, Secrets, Repo Connection (Slice 5, T-006) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Settings screen where the developer sets the platform's inputs (SQLite) and secrets (OS keyring only), sees and resets the repo connection, and from which *Needs setup* cards are resolved.

**Architecture:** The engine gains a `settings` module: a `002_settings.sql` migration keyed by platform name, a `SecretStore` trait (keyring in the app, in-memory in tests), validated setters, a `SettingsView`, and an ordered `disconnect`. `placement_status` takes a `SetupState`, so `needsSetup` lists only what's missing. The frontend adds `#/settings` inside Home, an in-app `Dialog`, an Onboarding pre-fill, and an *Open Settings* link on the card.

**Tech Stack:** Rust (pharos-engine, rusqlite_migration, `keyring` 4.x), Tauri 2 + tauri-specta `=2.0.0-rc.26`, SolidJS + `@solidjs/router`, vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-settings-inputs-secrets-design.md`

## Global Constraints

- A secret value is never returned to the frontend, written to SQLite, logged, or included in an error message.
- Set operations accept only names and keys declared by the applied platform manifest. Removing a stored row is allowed for any stored row.
- Keyring: service `io.pharos.desktop`, account `<platform>/<SECRET_NAME>`, native backends only (macOS Keychain, Linux Secret Service), no plain-file fallback.
- Inputs and secret names are keyed by Platform `metadata.name`, not by source id.
- In-app dialogs only, never `prompt()`, `alert()` or `confirm()`.
- `pharos-engine` stays Tauri-free. New types use `#[cfg_attr(feature = "specta", derive(specta::Type))]`. `app/src/bindings.ts` is only regenerated by `cargo test`.
- Exact copy from the spec:
  - "Available after the first sync"
  - "Not synced yet"
  - "Not set" / "Set"
  - "Saved"
  - "`<value>` is no longer offered, pick another"
  - "No longer used"
  - "Open Settings"
  - Disconnect dialog text: "Disconnect from `<url>`? The app forgets the repo, its dashboards and your approval. You'll connect again from the start."
  - Disconnect checkbox: "Also forget my details and secrets for `<platform title>`"
  - Disconnect dialog buttons: **Disconnect** and **Cancel**
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A pasted token with a trailing newline or spaces** is stored trimmed, and a whitespace-only value is refused with `invalidValue`. (Task 1 test `secret_values_are_trimmed_and_blank_is_refused`.)
2. **A keyring failure message never contains the value.** (Task 1 test `keyring_failure_records_nothing_and_hides_the_value`.)
3. **Disconnect while a sync review is pending** drops the plan, and the next `pending_sync` is `None`. (Task 3 test `disconnect_drops_a_pending_plan`.)
4. **An enum whose `from` directory is empty or missing** gives empty choices, and every value is refused rather than the app crashing. (Task 2 test `enum_with_missing_catalog_has_no_choices`.)
5. **A whitespace-only string input** clears the value, the same as empty. (Task 1 test `blank_string_input_clears`.)

  ```rust
      fn set(&self, account: &str, value: &str) -> Result<(), String>;
      /// Ok when the entry is already missing.
      fn delete(&self, account: &str) -> Result<(), String>;
  }

  impl Engine {

      pub fn open_with(data_dir: &Path, store: Box<dyn SecretStore>) -> Result<Self>;

      pub fn remove_stored(&mut self, platform: &str, kind: StoredKind, key: &str) -> Result<()>;

  // settings.rs
  #[serde(rename_all = "camelCase")] pub enum StoredKind { Input, Secret }
  ```
- New `EngineError` variants, with these messages:
  - `Undeclared(String)`: "`{0}` is not declared in pharos.yaml"
  - `InvalidValue { key: String, reason: String }`: "invalid value for `{key}`: {reason}"
  - `NoPlatform`: "nothing is applied yet; settings are available after the first sync"
  - `Keyring { name: String, message: String }`: "could not update secret `{name}` in the OS keyring: {message}"
  - The keyring `message` comes from the store and must not contain the value. `KeyringStore` maps errors with `e.to_string()`; the crate doesn't echo secrets.
- `run.rs`: `pub(crate) fn read_catalog(root: &Path, from: &str, max: usize) -> Result<Vec<serde_json::Value>, FileError>`. It confines `from` from the repo root (D-012) and reuses `walk` and parsing, with no approval check, because it isn't widget execution (decision D-029). A missing directory → `Ok(vec![])`.
- Choices: `settings::choices(root, def: &InputDef) -> Vec<String>`. These are the static `values`, or the string at the `field` dot path of each catalog row, unique and sorted. Read errors → empty.
- Validation:
  - `set_input`:
    - The key must be in `platform.spec.inputs`, else `Undeclared`.
    - `None`, empty or whitespace-only clears the row.
    - The value is trimmed.
    - For enum, the value must be in the choices, else `InvalidValue { reason: "not one of the choices" }`.
  - `set_secret`:
    - The name must be in `spec.secrets`.
    - The value is trimmed, and an empty result is `InvalidValue { reason: "empty" }`.
    - Write `store.set` first; on error return `Keyring` and leave no row. Otherwise upsert `secrets_meta (platform, name, set_at = now())`.
  - `remove_secret`: same as `remove_stored(platform, Secret, name)`, but requires a declared name.
  - `remove_stored`: for a secret, `store.delete` then delete the row; for an input, delete the row.
  - Everything returns `NoPlatform` before the first apply.
- `tests/common/mod.rs`: `MemoryStore { entries: Arc<Mutex<BTreeMap<String,String>>>, fail: Arc<AtomicBool> }` implements `SecretStore` (when `fail` is set, both `set` and `delete` return `Err("store unavailable")`). Also `Fixture::synced_engine_with(store)`.

- Rules:

  - Before the first apply: `platform: None` with empty lists, and `source` is still filled in.
  - `needsSetup` lists `refs − set`, and when nothing is missing, falls through to the remaining precedence.
  - `Engine::dashboards()` builds the `SetupState` once per call.

### Task 3: Engine — disconnect

**Files:** Modify `crates/pharos-engine/src/lib.rs`, `crates/pharos-engine/src/db.rs`. Test `crates/pharos-engine/tests/settings.rs`.

**Interfaces:**
- Produces `Engine::disconnect(&mut self, forget: bool) -> Result<()>`, in this order (spec):
  1. With forget, `store.delete` for each of the platform's `secrets_meta` names. On the first error, return `Keyring` and change nothing.
  2. With forget, delete the platform's `user_inputs` and `secrets_meta` rows.
  3. `self.pending = None` and delete the `sources` row (cascade).
  4. Remove the clone directory, ignoring errors.
- With no platform applied, forget only skips steps 1–2. `NoSource` if there is no source.
