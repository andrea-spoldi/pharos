# Platform Dashboards (Slice 4, T-005) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render the platform repo's `kind: Dashboard` manifests as read-only 12-column grids with a tab switcher, one shared widget frame for every state, a safe markdown view and the platform title, with Home shown after sync and no extra click.

**Architecture:** The engine turns the stored snapshot into `DashboardView`s, with each placement's widget manifest, a `PlacementStatus` and a repo-relative `reads` path. The frontend only renders that status. Two new Tauri commands, `list_dashboards` and `get_platform`. A hash router (`#/d/:name`) picks the dashboard inside Home. Widgets still run by name (D-021).

**Tech Stack:** Rust (cockpit-engine, cockpit-manifest, Tauri 2, tauri-specta `=2.0.0-rc.26`), SolidJS + `@solidjs/router` (hash router), `mdast-util-from-markdown`, vitest + @solidjs/testing-library.

**Spec:** `docs/superpowers/specs/2026-10-28-platform-dashboards-design.md`

## Global Constraints

- The frontend sends nothing executable: dashboards take no arguments, and runs send only the widget name (`run_widget(name)`, D-021).
- No `innerHTML` (or any raw-HTML escape hatch) anywhere. Repo markdown is rendered from an AST, and raw HTML nodes render as literal text.
- `crates/cockpit-manifest` and `crates/cockpit-engine` stay Tauri-free. New engine types derive `specta::Type` only via `#[cfg_attr(feature = "specta", derive(specta::Type))]` (D-016). Integers are exported as `u32` (D-018).
- `app/src/bindings.ts` is regenerated by `cargo test` and never hand-edited.
- Plain CSS with the existing tokens in `app/src/styles.css`. No component library. Light and dark both work.
- Grid: 12 columns, 80px row height, `grid-column: x+1 / span w; grid-row: y+1 / span h`. Below 900px, one column in `(y, x)` order with a capped card height.
- Tabs: the first 5 dashboards are tabs, the rest go in **More ▾** (closes on selection, outside click, Escape). A single dashboard still shows its tab.
- Platform title: `metadata.title` → `metadata.name` → `"Local IDP"`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Re-sync while viewing a dashboard:** after Sync now applies, runnable widgets re-run but keep showing their previous data. No skeleton flash. (Task 4 test `keeps data visible while re-running`.)
2. **The dashboard on screen is removed by a sync:** the view goes to the default dashboard (replace) instead of a blank grid. (Task 5 test `falls back when the current dashboard disappears`.)
3. **A dashboard with zero placements:** shows "This dashboard is empty." inside the tab, not a blank area. (Task 5 test `shows an empty dashboard notice`.)
4. **The same secret or user input referenced several times** (placement and source both use `{{ user.team }}`): `needsSetup` lists it once, sorted. (Task 1 test `dedupes and sorts setup refs`.)
5. **The More menu under keyboard use:** Escape closes it, and picking an entry navigates and closes it. (Task 5 test `more menu closes on escape and selection`.)

### Task 1: Engine — placement status (pure)

**Files:**
- Create: `crates/cockpit-engine/src/dashboard.rs`
- Modify: `crates/cockpit-engine/src/lib.rs` (add `mod dashboard;` and `pub use dashboard::{DashboardView, PlacementStatus, PlacementView};`)

**Interfaces:**
- Produces (all `Debug, Clone, PartialEq, Serialize` + `cfg_attr` specta):
  ```rust
  #[serde(tag = "kind", rename_all = "camelCase")]
  pub enum PlacementStatus {
      Missing,
      NeedsSetup { inputs: Vec<String>, secrets: Vec<String> },
      NotAvailable { feature: String },
      Static,
      Runnable,
  }
  pub struct PlacementView {
      pub widget: String, pub x: u32, pub y: u32, pub w: u32, pub h: u32,
      pub manifest: Option<Widget>, pub status: PlacementStatus, pub reads: Option<String>,
  }
  pub struct DashboardView { pub metadata: Metadata, pub placements: Vec<PlacementView> }
  pub(crate) fn placement_status(widget: Option<&Widget>, placement: &Placement) -> PlacementStatus
  ```
- Precedence: `Missing` (widget `None`) → `NeedsSetup` (any `user.*` / `secrets.*` refs) → `NotAvailable` → `Static` → `Runnable`.
- Refs are collected with `cockpit_manifest::template::refs` (make `template::refs` `pub` and re-export it from `cockpit-manifest/src/lib.rs` as `pub use template::refs as template_refs;`) over: every placement input value, and the widget source's templated fields (`http`: `url` + header values; `command`: `args`; `file`: none, since paths are literal per D-010). Keep only `Namespace::User` → `inputs`, `Namespace::Secrets` → `secrets`. Collect into `BTreeSet` (dedup + sorted). A template parse error contributes no refs (lint already rejects it).
- `NotAvailable.feature` copy, exact: `"command sources"`, `"http sources"`, `"the kv view"`, `"the raw view"`, `"markdown from a data source"`, and for a sourceless non-markdown view, `"the <type> view"` (lowercase type). Rules: command/http source → that source; file source with view `kv`/`raw`/`markdown` → that view (`markdown` → `"markdown from a data source"`); no source + `markdown` → `Static`; no source + other view → `"the <type> view"`; file + `table`/`list`/`card` → `Runnable`.

- Produces: `MarkdownView(props: { content: string })` and `WidgetFrame(props: { placement: PlacementView; version: number })`. The card element is `<article class="widget" style={grid placement}>`, with the title header `manifest.metadata.title ?? placement.widget`.
- Markdown mapping: heading depth d → `h{min(d+2, 6)}`; paragraph, emphasis, strong, inlineCode → `<code>`, code → `<pre><code>`, list (ordered → `ol`) / listItem, blockquote, thematicBreak → `hr`, break → `br`; link → children followed by ` (<url>)` in `<span class="muted">`; image → its alt text; `html` → its `value` as a text node; unknown nodes → render their children, if any.
- Frame copy, exact:
  - Missing: title **Missing widget**, body `This dashboard places <code>{name}</code>, which the platform repo doesn't define.` (`role="alert"`).
  - Needs setup: title **Needs setup**, body `Needs your <strong>team</strong>` for inputs, `Needs secret <strong>GITLAB_TOKEN</strong>` for secrets, joined with `· `.
  - Not available: title **Not available yet**, body `{feature} arrive in a later version.`
  - Loading: `<div class="skeleton" aria-busy="true" aria-label="Loading">`.
  - Error: titles as the old `errorTitle` (permissionDenied → Access denied, dataError → Could not read the data, else Could not run this widget), message in `<details><summary>Details</summary><pre>`.
  - Empty: `No data in <code>{reads}</code>.`
- Only `runnable` placements call `runWidget`. The run resource is keyed on `[widget, version]`, and the view reads `data.latest` so a re-run keeps old rows (no skeleton when `latest` exists).

Routing: `index.tsx` renders `<HashRouter><Route path={["/", "/d/:name"]} component={App} /><Route path="*" component={() => <Navigate href="/" />} /></HashRouter>`. If the installed `@solidjs/router` major differs, use its equivalents. `Dashboards` reads `useParams().name` and navigates with `useNavigate()(\`/d/${name}\`, { replace: true })`.
- Behaviour:
  - Default = first of `listDashboards()` (the engine puts `home` first).
  - Redirect with replace when `name` is missing or unknown and the list is non-empty. This also covers a dashboard that disappeared after a sync.

  - Zero dashboards → `The platform repo defines no dashboards yet.` with no `nav`.
  - Zero placements → `This dashboard is empty.`
  - Tabs: `<nav aria-label="Dashboards">` with buttons or links using `aria-current="page"` on the current one.
  - More menu: `More ▾` button, the list closes on selection, Escape (keydown on document) and outside click.
- Home: header `<h1>` is the platform title (resource on `getPlatform`, keyed on the sync version; fallback chain from Global Constraints). `WidgetList` → `<Dashboards version={widgetsVersion()} />`. `<main class="screen wide">`. The pending review still replaces the main area, and the never-synced notice is unchanged.
- Tests render inside `<MemoryRouter history={createMemoryHistory()}>` (or the installed version's memory router) with the same `Route` shape, starting at a given path.
