# Sidebar navigation — design (T-022 decision, built as T-024)

Replace the top bar + dashboard tab strip with a left sidebar, and give the page
a slim header that only carries actions for the current dashboard. This is the
"Option B" layout validated in the A/B comparison (artifact *Pharos — A/B: tabs
vs sidebar*). Use it as the visual spec: it renders the real `styles.css` from
`main` plus the sidebar layer described below.

T-022 ("Decide + design: sidebar navigation") is closed by this document; its decision is **D-040** (D-039 went to T-023). The build is **T-024** (L, decomposed into plan tasks: `docs/superpowers/plans/2026-11-27-sidebar.md`).

Follow the usual workflow (CLAUDE.md, SESSIONS.md, session planner): TDD, own
branch, bindings drift check, demo script, decisions logged. `DESIGN.md` and
`.impeccable/design.json` are generated by **impeccable**: update the design
definition there and regenerate. Don't hand-edit them.

**Scope:** frontend only. No engine, manifest, IPC or migration changes. No new
dependencies.

---

## Approaches considered

- **A. Keep the tabs** (5 + More ▾), top bar unchanged. Widest grid, no new pattern; but dashboards past the
  fifth hide under More, tabs don't group by origin, and the 198px chrome above the first widget stays.
- **B. Left sidebar (chosen by user)**, collapsible to a rail, grouped by origin, global actions in its footer,
  a slim page header for per-dashboard actions. Familiar to users coming from Backstage and similar IDPs.
- **C. Tabs + palette only** (defer navigation to T-012). Rejected: the palette is the fast path, not a
  browsable one; it doesn't fix overflow or grouping.

## What the A/B measured (why B)

| | A (tabs) | B (sidebar) |
|---|---|---|
| First widget starts at | 198px | **84px** |
| Grid width @1440, sidebar open | **1376px** | 1136px |
| Grid width @1100, sidebar collapsed | **1036px** | 980px |
| Dashboards one click away (9 total) | 5 / 9 | **9 / 9** |

The sidebar costs width when open, and almost nothing when collapsed. In
exchange, every dashboard is visible and grouped by origin, and about 114px of
vertical space goes back to widgets.

---

## Decisions (answers to T-022's open questions; logged as D-040)

1. **Replaces the tabs entirely** at widths above 900px. Not just the "More" overflow.
2. **Grouped by origin:** *Platform* (platform templates, `home` first, then the
   engine's order) and *Mine* (user dashboards, including customized forks, in
   the engine's order). The landing star follows the landing dashboard into
   either group.
3. **Collapsible to a 56px rail.** User choice is saved per device in
   `localStorage` (`pharos.sidebar` = `open` | `rail`, same pattern as
   `pharos.theme` in `app/src/theme.ts`). With no saved choice, the default is
   `open` when `window.innerWidth >= 1280`, else `rail`.
4. **Sync status, Sync now, the source and Settings move into the sidebar.** The
   page header keeps only the dashboard title and the actions for that dashboard.
5. **Below 900px** the sidebar is not rendered. A compact top bar replaces it
   (see *Narrow windows*).
6. **Default window** grows from 1200×800 to **1360×860** in
   `src-tauri/tauri.conf.json`, so a fresh install opens with the sidebar open
   and a comfortable 12-column grid (~1056px wide).
7. **The command palette (T-012) stays.** It's the fast path once there are
   many dashboards. The sidebar is the browsable path. They don't replace each other.

### Sidebar (`app/src/components/Sidebar.tsx`, new)

- **Top:** `PharosMark` + the platform title (what the top bar's `h1.brand`
  shows today). Below it, the source as `owner/repo · branch` in muted small
  text, ellipsised, with the full URL in a `title` and in the accessible name.
- **Two `<nav>` landmarks:** `aria-label="Platform dashboards"` and `aria-label="Your
  dashboards"`, each with a small uppercase heading. Items are buttons (as the
  tabs are today) that navigate to `/d/:id`. The current one has
  `aria-current="page"`.
- **Item:** a 22px monogram tile (first letter of the title) + the title. The
  landing item keeps the existing cue: decorative `★` plus the sr-only
  "(Landing dashboard)" text in its accessible name, exactly as the tabs do now.
- **"+ New dashboard"** sits at the end of *Mine*. It opens the **same** create
  dialog the toolbar opens today (move or expose it from `DashboardEditor.tsx`;
  don't duplicate the flow). After creating, navigate to the new dashboard, as
  today.
- **Footer** (pinned to the bottom, `margin-top: auto`): the sync status live
  region (must stay **always mounted**, as today, so screen readers announce
  changes), the short commit, a **Sync now** button (disabled while busy, label
  "Syncing…"), then **Settings** as a nav item (`aria-current="page"` on `/settings`).
- **Collapse toggle:** a button at the top or bottom of the sidebar with
  `aria-expanded` and `aria-label="Collapse sidebar"` / `"Expand sidebar"`.
  Shortcut **⌘\\ / Ctrl+\\** toggles it. Ignore the shortcut while typing in an
  input or a dialog is open.
- **Rail mode (56px):** only the mark, monograms, sync icon button (`↻`, with
  `aria-label="Sync now"`) and settings icon are visible. **Labels stay in the
  accessibility tree**: hide them with the existing `.sr-only` pattern, *not*
  `display: none` (the A/B mockup used `display: none`; don't copy that). Show
  the title as a tooltip on hover **and** on keyboard focus.

### Main area

- **Page header** (`header.page-head`): `h1` = the current dashboard's title
  (1.35rem, 650, `-0.015em`), and under it a muted line: *Platform dashboard ·
  read-only* or *Your dashboard*. Actions on the right: the existing
  `DashboardToolbar` **minus "+ New dashboard"** (Customize / Edit-Done / Add
  widget / New group / Rename / Set as landing / Delete, with the same rules as today).
- The sync review (`SyncReview`), the changelog notice and the sync error notice
  render at the top of the main area, above the page header, as today.
- **Settings** renders in the main area with the sidebar still visible. Remove
  the "← Back to dashboards" link (the sidebar is the way back). Keep
  `lastDashboard` only if something else still needs it.
- Never-synced state: the sidebar shows the brand, source and footer with no
  dashboard sections; the main area keeps the existing "Review the repo" notice.

### Narrow windows (≤ 900px)

- No sidebar. A compact top bar: mark + current dashboard title as a button
  (`Home ▾`) that opens the existing `.menu` with both groups (headings
  included), then Sync now and Settings.
- Everything else (single-column grid, inert drag/resize) is unchanged.

## State and data

- The dashboard list is currently loaded inside `Dashboards.tsx`. Both the
  sidebar and the page need it, so **lift it** into `Home.tsx` (or a small store
  module) and pass it down. One resource, one refetch. Every action that changes
  the list (create, rename, delete, customize, set/clear landing, sync) must
  refresh the sidebar too. Add a test for each of create, rename and delete.
- Routing is unchanged: `HashRouter` with `/`, `/d/:id`, `/settings` (`index.tsx`).
- Sidebar mode lives in a tiny module like `theme.ts` (`sidebar.ts`): read once,
  synchronously, on startup (no flash of the wrong width), write on toggle, and
  wrap `localStorage` in try/catch.

## CSS

Add a sidebar section to `app/src/styles.css`. **Existing tokens only**, no new
colours or shadows. The current item follows the Halo Rule (`--accent-wash`
background) plus a 3px `--accent` bar on its inner edge. That marks *place*, so
it fits the One Lamp Rule. Starting point (from the A/B, with the fixes below):

```css
.app-shell { display: grid; grid-template-columns: 240px minmax(0, 1fr); min-height: 100vh; }
.app-shell.rail { grid-template-columns: 56px minmax(0, 1fr); }
.sidebar {
  box-sizing: border-box;          /* REQUIRED: styles.css has no global border-box;
                                      without it the padding overflows 100vh and
                                      pushes Settings off-screen (seen in the A/B) */
  position: sticky; top: 0; height: 100vh; overflow: auto;
  display: flex; flex-direction: column; gap: var(--space-3);
  padding: var(--space-3) var(--space-2);
  background: var(--surface); border-right: 1px solid var(--border);
}
.nav-item { position: relative; display: flex; align-items: center; gap: var(--space-2);
  width: 100%; padding: 6px var(--space-2); text-align: left; color: var(--muted);
  background: none; border: none; border-radius: var(--radius); }
.nav-item:hover { color: var(--fg); background: var(--surface-2); }
.nav-item[aria-current="page"] { color: var(--fg); font-weight: 600; background: var(--accent-wash); }
.nav-item[aria-current="page"]::before { content: ""; position: absolute; left: -8px; top: 6px; bottom: 6px;
  width: 3px; border-radius: 0 3px 3px 0; background: var(--accent); }
.main { min-width: 0; padding: var(--space-3) var(--space-4); display: flex; flex-direction: column; gap: var(--space-3); }
```

Also:
- Add `.nav-item` to the hover exclusion list on the global `button:hover` rule
  (as `.tab` and `.menu-item` are), and to the `prefers-reduced-motion:
  no-preference` transition list.
- Animate the column width change on collapse (150ms) only under
  `no-preference`. Under `reduce`, switch instantly.
- Remove the `.tabs` / `.tab` / `.more` rules once nothing uses them. Keep
  `.menu` / `.menu-item` (the narrow top bar reuses them).
- The beam (`body::before`) and hairline (`body::after`) stay as they are. The
  opaque sidebar covers them, so they show over the main area only. That's
  intended.
