# Pharos

Desktop "local IDP": Tauri 2 + SolidJS app that renders a platform team's git repo
(widgets, dashboards, catalog YAML). Design: `docs/restart-plan.md`. Session state: `SESSIONS.md`.

## Security — read first
- Backend executes widgets from the **stored manifest only** (`run_instance(id)`); never accept
  URLs, headers, executables, args or secret names from the frontend.
- Secrets: values only in OS keyring, names only in SQLite; resolve only secrets declared in the manifest.
- File sources are confined to the platform repo root (canonicalise + allow-list).
- Enforce approved capabilities at execution time, even after consent.
- Strict CSP; never `csp: null`.

## Architecture constraints
- `crates/pharos-manifest` and `crates/pharos-engine` must not depend on Tauri.
- `app/src/bindings.ts` is generated by tauri-specta — never hand-edit; all commands derive `specta`.
- Git: shell out to system `git`; the clone in app data is app-owned (`fetch` + `reset --hard`).
- Migrations via `rusqlite_migration` (`user_version`), not re-run DDL.
- No browser `prompt()`/`alert()` — in-app dialogs only.

## Intentional decisions
- No WASM, no personal widgets, no background sync, no Windows in v1.
- Permissions are derived from `spec.source`, not hand-declared.

## Workflow
- Every slice ends with green tests + a demo script in `docs/demos/<slice>.md`, run in the real app.

## Stack shorthand
- Rust (Tauri 2, tauri-specta, rusqlite), TS (SolidJS, Vite, @solidjs/router), plain CSS tokens
- Tests: `cargo test`, `vitest`; lint: `cargo clippy`, `tsc`
- Commands: `npm run dev` (tauri dev), `cargo test` (also regenerates bindings), `npm test -w app`, `npm run typecheck -w app`, `cargo run -p pharos-cli -- lint <repo>`
- Lint snapshots (insta): `INSTA_UPDATE=always cargo test -p pharos-manifest`, then review the `git diff`.
- tauri-specta/specta are pinned `=2.0.0-rc.26` — bump together or not at all.
